## Frozen ProjectV3 JSON/types

Entry `packages/creator-core/src/v3.ts` exports all types and functions below. New schema `schemas/creator-project-v3.schema.json`. No v1/v2 mutation/migration.

`ProjectV3 = {version:3,name:string,width:number,height:number,fps:number,durationFrames:number,layers:LayerV3[]}`.
`PropertyV3 = 'x'|'y'|'scaleX'|'scaleY'|'rotation'|'opacity'|'skew'|'skewAxis'`.
`EasingV3 = 'linear'|'ease-in'|'ease-out'|'ease-in-out' | {type:'cubic-bezier',x1:number,y1:number,x2:number,y2:number}`. All four custom coordinates 0..1: deliberately bounded monotone-progress subset; overshoot is authored in explicit numeric keys, not unsupported easing overshoot. Outgoing-segment convention as v2.
`KeyframeV3 = {frame:number,value:number,easing:EasingV3}`.
`PathGeometryV3 = {closed:boolean,vertices:[number,number][],inTangents:[number,number][],outTangents:[number,number][]}` (relative tangents, same v2 origin convention).
`MaskV3 = {name:string,mode:'add'|'subtract',inverted:boolean,opacity:number,path:PathGeometryV3}`. Static LOCAL path, at most four masks per non-group; no implied group clipping, image assets or animated mask paths.
`TrimV3 = {start:number,end:number,offset:number,tracks:{start:KeyframeV3[],end:KeyframeV3[],offset:KeyframeV3[]}}`. start/end percent 0..100, offset degrees -3600..3600. Only path layers may have non-null trim. It trims that path's geometry, not opacity simulation.
Common REQUIRED fields: `{id,name,parentId,x,y,pivot:[number,number],scaleX,scaleY,rotation,opacity,skew,skewAxis,tracks:Record<PropertyV3,KeyframeV3[]>,masks:MaskV3[],trim:TrimV3|null}`.
- `group`: common + `type:'group'`, opacity 100/empty opacity track, masks [], trim null; no geometry/paint extras.
- `rect`/`ellipse`: common + `type,width,height,cornerRadius,fill,stroke,strokeWidth` (same v2 primitive restrictions); trim null.
- `path`: common + `type:'path',path,fill:string|null,stroke,strokeWidth,pathKeys:{frame:number,value:PathGeometryV3,easing:EasingV3}[]`. All path keys must match base path topology, closure and count. Open path fill null and endpoint tangent rules unchanged.
All schema fields required; no unknown fields. Hard budgets: same v2 artboard/fps/duration/text/graph/coordinate/channel ranges, except independent scales 1..1000, skew -75..75, skewAxis -3600..3600. <=100 layers, 256 vertices/path, 2048 base+mask vertices, <=100 keys/channel or geometry track, <=10000 keys total; morph vertices across keys <=16384. Same strict JSON duplicate/depth/byte limits. Native and TS must agree on conservative finite world limits including skew and independent scales. Static mask bounds must be checked. Groups remain transform-only; flat bottom-to-top paint ordering remains.
Lottie ks uses s:[scaleX,scaleY,100], r, sk, sa, a and p. Derive exact skew sign/axis order from installed official lottie-web and test against independent rendered SVG CTM; do not guess. Export `masksProperties`, `tm`, animated `sh` with genuine geometry keys. Reject export complexity/size overflow without crashing editor. Preserve candidate/save availability on preview failure.
Core API: `parseProjectV3(text:string):ProjectV3`, `validateProjectV3(value:unknown):asserts value is ProjectV3`, `serializeProjectV3(project):string`, `exportLottieV3(project):Record<string,unknown>`, `evaluateLayerV3(layer,frame):LayerV3` (sample numeric channels + path morph + trim; preserve identity and metadata), `worldMatrixV3(project,id,frame):[number,number,number,number,number,number]`, `blankProjectV3():ProjectV3`. Additional helpers allowed. Schema owner = TS core worker. Native worker follows this explicit field contract while schema arrives.

## Frozen Director HTTP/data contract

`POST /api/ai/director/jobs` exact JSON `{provider:'codex'|'claude',prompt:string,consent:true,stage:'style'|'poses'|'motion',approved:DirectorProposal|null,contextConsent:boolean}`. Prompt trimmed 1..4000 Unicode scalars. Existing global HTTP MAX_REQUEST remains 131072 UTF8 bytes; Director selected-prior envelope additionally has a 65536-byte UTF8 native context cap. Client preflights BOTH serialized sizes and fails before POST if either cannot fit, preserving proposal/save/export without truncation. Director guidance asks for compact output; a generated large-but-valid document is not promised to fit contextual transfer. Style requires approved null and contextConsent false. Poses requires approved stage style; motion requires approved stage poses; both require contextConsent true and strict native validation of prior envelope/project. Never infer consent from presence. Duplicate keys rejected. Selected prior proposal ONLY crosses contextual boundary, not editor contents/repository. At most one generated proposal per request.

`DirectorProposal = {version:1,stage:'style'|'poses'|'motion',summary:string,review:{focalPoint:string,silhouette:string,material:string,choreography:string,limitations:string},poses:{frame:number,label:string}[],project:ProjectV3}`. Summary max1200 UTF16; review values nonblank max600; 1..5 distinct strictly increasing valid pose frame indices, labels nonblank max200. Style must have ONE pose at frame0, contain at least one non-group layer with positive opacity and fill or nonzero stroke paint, and have NO animation keys anywhere (numeric, path, trim). Empty/group-only/fully transparent/unpainted scaffolding is rejected as empty_style; a blank manual editor remains a valid ProjectV3. Painted geometry is eligibility, not proof of semantic completeness, in-artboard visibility or artistic approval. The style must include all actors needed by later animation because the approved cast is locked; no promises to add artwork later. Poses stage 3..5 frames; motion stage 1..5 frames. Response stage must equal requested stage. Stage summary/review is model commentary, not a trusted artistic verdict or instructions.

### Design continuity gate (not a decorative wizard)

Between stages, preserve the approved project's artboard/fps/duration, layer identity/order/type/parent graph, pivot, static numeric defaults, paint, primitive dimensions/radii, base path geometry and masks. Only project name, proposal commentary/pose labels, animation tracks, pathKeys and trim numeric animation may change. Do not regenerate a different illustration after accepting the style. Motion must preserve the approved pose frame list and every already-authored numeric/path/trim key's frame and value; outgoing easing may be refined and intermediate keys may be added. Frontend additionally samples ALL layers at approved pose frames and rejects any numeric/path/trim pose drift (tolerance 1e-5), including newly animated channels. Backend enforces immutable design and retained authored keys; frontend sampling closes the implicit-channel drift gap before review/Apply. These tests are needed to show that the stage approvals actually constrain output. No silent repair of a drifted candidate.

Shared GET `/api/ai/jobs/{id}` and cancel. Success job exposes `proposal:DirectorProposal` and `kind:'director'`, provider/id/status. Start response `{ok:true,job:{id,status:'running',provider,kind:'director'}}`. All v1/v2/Harness/Director share existing single admission slot and process isolation/cancellation/reaping/timeouts. No provider tools/hooks/MCP/assets/expressions; no repair/fallback. Native `creator_v3.rs` exposes `parse_project_v3`, `validate_project_v3`; `provider_director.rs` exposes schema/prompt/request/generate plus envelope validation as needed. Existing v2 prompt also receives bounded matched guide without changing its request/output contract.
