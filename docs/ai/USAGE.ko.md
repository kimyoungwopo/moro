# 내 Codex·Claude Code로 애니메이션 만들기

Moro 계정을 만들거나 API 키를 입력하지 않고, 이 컴퓨터에 설치된 공식 AI CLI를 연결하는 첫 버전이다. 프론트엔드/애니메이션 코어는 TypeScript, 로컬 연결 서버는 Rust다. 수동 제작·색상 편집에는 AI 서버가 없어도 된다.

## 준비와 실행

Node22.13+와 Rust/Cargo, 사용할 공식 CLI가 필요하다. 사용자 본인이 공식 CLI의 로그인 절차를 완료해야 한다. 앱은 로그인 토큰을 읽거나 복사하지 않으며, 기존 CLI 계정의 사용량·요금 정책이 적용된다. 무료 사용이나 API 요금 포함을 보장하지 않는다.

저장소 루트에서:

```sh
npm ci
npm run build
npm run ai:build
npm run ai:serve
```

브라우저 주소:

```text
http://127.0.0.1:4174/create
```

`npm run dev` 또는 기존 정적 서버만으로는 AI 연결이 활성화되지 않는다. Rust 서버가 빌드된 앱과 API를 같은 출처에서 제공한다. 포트 변경은 `bridge/target/debug/moro-ai-bridge --web-root dist --port 4175`처럼 서버 인자로 지정한다. 터널·외부 IP·원격 공개는 이 버전의 범위가 아니다.

현재 macOS/ARM64에서 Rust1.99.1, Codex CLI0.153.4, Claude Code2.1.105를 검사했다. manifest의 Rust 최소 버전은1.85이나 최소 버전 자체는 별도 시험하지 않았다. POSIX 프로세스 그룹을 사용하므로 Windows용 연결 서버는 지원하지 않으며 Linux 실행은 별도 검증 대상이다.

## 실제 사용 흐름

1. Creator의 **AI assistant**를 연다.
2. **AI provider**에서 사용할 CLI를 선택한다. `installed`는 실행 파일을 찾았다는 뜻이며 로그인·생성 성공을 뜻하지 않는다.
3. **Animation brief**에 도형·타이밍·이동을 적고 **Target display size**64/128/512를 선택한다. 이는 실제 표시 크기이며 캔버스 크기와 다르다. 선택값은 Design target 헤더로 본문과 함께 전송된다. 전체4000자 제한 안에서 본문을 자르지 않으며 화면의 실제 입력 한도를 따른다. 비밀번호·개인정보를 넣지 않는다.
4. 기본 **AI mode → New motion**에서는 brief·표시 크기 전송에 동의한 뒤 **Generate proposal**을 누른다. 현재 프로젝트나 저장소는 보내지 않는다.
5. **Proposal preview**에서 실제 결과를 재생하거나 **Proposal frame**으로 이동한다. **Proposal size**64/128/512px로 작은 크기 가독성·잘림과 수치 경고를 확인한다. 경고가 없다고 미학적 품질이 보증되는 것은 아니다. 이 시점에는 기존 캔버스가 바뀌지 않는다.
6. 결과를 확인한 뒤 **Apply proposal**을 눌러 하나의 편집으로 적용한다. **Undo** 한 번으로 이전 애니메이션을 복원한다. 새 작품을 다시 요청하려면 New motion에서 brief를 고치고 재동의한다. 현재 작품을 바탕으로 수정하려면 아래 Refine current project를 선택한다. 미리보기·수치 경고·저장소는 보내지 않는다.
7. **Save project**로 편집 원본을, **Export Lottie**로 실제 애니메이션 JSON을 받는다.

예시 brief: “512×512, 60fps, 120프레임. 청록색 원 하나가 왼쪽에서 오른쪽으로 부드럽게 갔다가 처음 위치로 돌아오는 루프.”

## 현재 작품 수정과 로컬 재사용

- **AI mode → Refine current project**: 현재 프로젝트의 이름·도형·색상·크기·키프레임을 보낸다는 별도 동의가 필요하다.1–20레이어/64KiB까지이며, 공급자·brief·표시 크기·원본이 바뀌면 다시 동의해야 한다. 예제는 Motion library에서 먼저 열 수 있다.
- **Changes from submitted project**: 추가·삭제·변경 레이어와 설정/순서 변경을 확인한다. 이는 구조 비교이지 미학적 품질 승인이나 요청 외 변경이 없다는 보증이 아니다.
- 요청 뒤 원본을 편집했다면 Apply가 막힌다. 그 편집을 Undo하거나 새 원본으로 다시 요청한다. 실제 변경이 없는 제안은 Apply하지 않아 Undo 이력을 소비하지 않는다.
- **Save proposal locally**: AI가 반환한 제안 원본을 적용 없이 IndexedDB에 저장한다. **Motion library → Save current project**는 현재 편집본을 별도로 저장한다. 예제 열기는 AI 호출이 아니며, 과거 실제 AI 생성물임을 표시한다.
- 브라우저·주소(origin)별 최대12개이며 꽉 차면 새 저장을 거부하고 기존 항목을 지우지 않는다. 삭제 확인을 취소하면 보존한다. 사이트 데이터를 지우면 사라지므로 프로젝트 파일 백업도 권장한다. 자동 저장·클라우드 동기화는 없다.

새 애니메이션과 기존 프로젝트 문맥 수정을 지원하지만 이미지·텍스트·SVG·임의 경로 생성은 여전히 지원하지 않는다. 실제 컨페티1회 수정 검증과 전체 회귀는 [제품2차 결과](PRODUCT-ITERATION-2-RESULT.ko.md)에 기록한다.

## 검증 결과 — 2026-10-31

- Rust 네이티브 HTTP/프로세스/프로토콜/검증 검사 **29개**를 부모에서 재실행해 통과했다. 기본 검사는 모델을 호출하지 않는다.
- 통합 앱 단위 **95개**, 브라우저 **18개**, 배포 **3개**, 문서 **6개**, lint/typecheck/build 통과. 브라우저18개 중 AI 프로토콜2개는 명시적인 가짜 HTTP 응답 검사다.
- 디자인/모션 기준·둥근 모서리·목표 표시 크기를 실제 생성에 연결하고 체크 접합/작은 배지2종을 재검증한 최신 결과는 [디자인 품질 수정](DESIGN-QUALITY-RESULT.ko.md)을 참고한다.
- 좌표·레퍼런스 전달 수정, 같은 요청3종 실제 재생성, Apply 전 실제 미리보기·수치 경고 및 별도 실제 Codex 통합 검증은 [품질 수정 결과](QUALITY-FIX.ko.md)를 참고한다.
- 별도 **실제 Codex + Rust 서버 + 브라우저** 검사에서 `Teal glide` 생성 성공. 사용자 동의, 적용 전 기존 사각형 보존, 명시적 적용, 편집 프로젝트/Lottie 실제 다운로드, frame0/60/119의 Creator·독립 플레이어 위치 일치, Undo1회로 기존 프로젝트 복원을 확인했다. 가짜 CLI나 HTTP 가로채기를 사용하지 않았다.
- 첫 실제 생성은 구조·다운로드 검사에는 통과했지만 scale/opacity를1로 생성해 거의 보이지 않는 결함을 시각 QA에서 발견했다. 원본을 수정하지 않고 별도 보존했다. 스키마·모델 지침에 percentage 단위(정상값100)를 명시하고 회귀 RED→GREEN 후 같은 brief를 실제로 재생성했다. 두 번째 결과는 scale100/opacity100,96px 원으로 실제 화면에서 정상 표시됐으며 표시 크기·투명도 검사도 추가 통과했다. 이 한 사례의 성공이 모든 AI 결과의 미학적 품질 보증은 아니다.
- **Claude 실제 생성은 미검증/차단 상태**다. 로그인 캐시 조회는 성공했지만 실제 요청은 OAuth401(토큰 무효)로 실패했다. 사용자가 공식 CLI에서 재로그인한 후 별도 확인해야 한다. 앱이 인증 파일을 고치거나 로그인 절차를 자동 수행하지 않는다.

## 안전 경계와 한계

브라우저에 키·토큰을 저장하지 않는다. 공식 CLI만 인증을 처리한다. CLI는 빈 앱 소유 작업 폴더에서 데이터 제안만 만들며 도구·셸·브라우저·MCP·플러그인·훅 사용을 제한한다. Codex는 read-only sandbox를 유지한다. 모델 결과를 Rust와 기존 편집 코어에서 각각 검증하며 코드로 실행하지 않는다.

서버는 IPv4 loopback만 수신한다. Host/Origin/JSON·전용 헤더를 검사하고 한 번에 생성1개,180초 제한, 출력 용량 제한, 작업별 취소·소유 프로세스 정리를 적용한다. 이것은 동일 사용자 프로세스로부터의 격리나 공개 서비스 보안 보증이 아니다. 불완전 요청의 소켓 deadline, SIGKILL 이후 정리, 악의적으로 그룹을 탈출한 자식까지 보장하지 않는다. CLI의 향후 버전·모든 관리형 계정 설정도 전수 검증하지 않았다.

상세 DTO와 구현 경계는 [계약](CONTRACT.md), 서버 사용법은 [Rust README](../../bridge/README.md)를 참고한다. 원격 push·공개 배포는 하지 않았다.
