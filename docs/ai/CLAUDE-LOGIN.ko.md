# Moro에서 Claude 로그인 연결

Moro 계정을 새로 만드는 기능이 아니다. 사용자가 설치한 **공식 Claude Code CLI**의 인증으로 연결한다. Moro는 암호·인증 코드·토큰·API 키를 입력받거나 브라우저 저장소에 보관하지 않는다. 공식 CLI가 자신의 인증 정보를 관리하며, 해당 계정의 사용량·한도가 적용된다.

## 사용 순서

1. Rust 로컬 브리지로 Moro를 연다. 일반 정적/dev 서버에는 인증 실행 기능이 없다.
2. 기본 만들기의 AI assistant/Quality lab, Rig 또는 Studio에서 제공자를 **Claude**로 선택한다.
3. **로그인 상태 확인**을 누르면 공식 CLI의 읽기 전용 상태만 조회한다. 모델 생성 요청은 하지 않는다.
4. **Claude 로그인**을 누르고 안내를 읽은 뒤 명시적으로 동의한다.
5. **공식 로그인 시작**은 macOS에서 브리지가 실행되는 컴퓨터의 Terminal을 열도록 요청한다. 처음에는 macOS가 Terminal 제어 권한을 물을 수 있다. 요청이 수락됐다는 메시지는 로그인 성공을 뜻하지 않는다.
6. 열린 Terminal과 공식 브라우저 화면에서 사용자가 인증을 완료한다. 브라우저가 코드를 보여주면 **공식 CLI의 Terminal에만** 입력한다. Moro나 채팅에 붙여넣지 않는다.
7. Moro로 돌아와 **로그인 상태 확인**을 다시 누른다. 실제 생성은 별도 생성 동의 후 실행한다.

사용하는 공식 명령은 다음과 같다. API 과금용 Console 로그인이나 토큰 발급으로 자동 전환하지 않는다.

```sh
claude auth login --claudeai
claude auth status --json
```

## 상태 메시지를 해석하는 방법

- **CLI 로그인 정보가 있어요**: 공식 CLI가 로그인 정보를 보고했다. 만료 여부나 실제 모델 호출 성공을 검증한 것은 아니다. 이전에 401이 발생했다면 다시 로그인할 수 있다.
- **Claude 로그인이 필요해요**: CLI가 로그아웃 상태를 보고했다.
- **로그인 상태를 확인하지 못했어요**: 타임아웃·잘못된 응답·실행 실패 등이다. 성공으로 바꾸어 표시하지 않는다.
- **Claude CLI가 설치되어 있지 않아요**: 사용자가 공식 CLI를 설치하고 브리지를 다시 실행해야 한다. Moro가 자동 설치하지 않는다.
- **업데이트가 필요해요**: 현재 CLI의 인증 명령을 확인할 수 없는 경우다. 사용자 승인 없이 업데이트하지 않는다.

Linux 등 자동 Terminal 연결을 지원하지 않는 환경이나 macOS 권한 거절 시에는 **로그인 명령 복사**로 위 공개 명령을 직접 실행한다. 코드나 암호를 복사하는 버튼이 아니다. 원격 기기의 브라우저를 여는 기능도 아니며, 인증 Terminal은 로컬 브리지가 실행되는 컴퓨터에 열린다.

## 동의·개인정보 경계

- 제공자 선택/화면 진입만으로 로그인은 시작되지 않는다. 취소·Escape·동의 누락은 실행하지 않는다.
- 로그인 요청에는 동의 여부만 보내며, 브리프·현재 프로젝트·저장소를 보내지 않는다.
- 인증 URL, 이메일, 계정/조직 ID, CLI 원문 출력이나 설정 경로는 브라우저 응답에 포함하지 않는다.
- 생성 또는 취소 정리가 진행 중이면 로그인 실행을 막는다. 짧은 로그인 실행 연결 중에는 새 생성을 막으며, 중복 Terminal 실행에는 별도 제한을 둔다.
- 로그인은 한 번씩만 시작한다. 실행 결과가 불확실해도 자동으로 다시 열지 않는다. 사용자 Terminal을 강제로 닫거나 종료하지 않는다.
- 로그아웃·계정 삭제·자체 OAuth 서버·공용 API 키는 추가하지 않는다.

## 실행

Node 및 Rust/Cargo, 공식 Claude Code CLI가 준비된 환경에서:

```sh
npm ci
npm run build
npm run ai:build
npm run ai:serve
```

브리지는 기본적으로 loopback의 4174 포트를 사용한다. Studio는 `/studio`, 기본 만들기는 `/create`, Rig는 `/rig`다. 공개 서버나 다른 기기의 localhost로 접속하는 설명이 아니다.

## 검증 범위

구현 계약은 `CLAUDE-LOGIN-CONTRACT.md`에 있다. 실제 네이티브 HTTP와 UI 검사는 별도의 **오프라인 CLI/Terminal 연결 fixture**로 동의·개인정보·상태 전환·문서 불변을 확인한다. 이 fixture가 성공해도 실제 계정의 브라우저 승인이나 모델 사용 가능 여부가 검증된 것은 아니다. 실제 로그인 완료는 사용자가 공식 화면에서 수행해야 한다.

구현 시 설치된 CLI 2.1.105의 `auth login --help`와 `auth status --help`를 직접 확인했다. 참고한 공식 문서는 Claude Code Authentication 및 CLI reference다. 최신 온라인 문서에만 있는 옵션을 설치된 CLI가 지원한다고 가정하지 않는다.

- https://code.claude.com/docs/en/cli-reference
