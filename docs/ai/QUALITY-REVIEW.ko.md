# Moro 실제 AI 결과 품질 검토

> 이 문서는 **제품 코드 수정 전 baseline** 기록이다. 좌표·모델 지침 전달·미리보기/경고 개선 이후의 검증은 [품질 수정 결과](QUALITY-FIX.ko.md)를 참고한다. 실패 원본과 아래 판정은 이력으로 보존한다.

검토일: 2026-10-31. 현재 로컬 Rust bridge + 공식 Codex CLI 경로를 사용했다. 제품 코드는 수정하지 않았다. 원본3종과 추가 지시 비교1종, 총4회의 실제 생성이며 Claude/다른 계정/모든 모델에 대한 일반 성능 평가가 아니다.

## 결론

**기본적인 UI 모션 제작 가능성은 확인했다. 그러나 현재 상태에서 고품질 결과가 안정적으로 자동 생성된다고 보증할 수는 없다.** 구조 검증과 파일 출력은4종 모두 통과했지만 기본 결제 완료 결과는 구도·체크 형태가 실패했다. 명확한 계약 지시를 추가한 별도 생성은 개선됐다. 이 비교만으로 특정 프롬프트의 통계적 우수성이나 일반 성공률을 주장하지 않는다.

## 동일 조건과 증거

- 실제 UI에서 동의 → Generate → Apply → Save project/Export Lottie 순으로4종을 내려받았다. 가짜 CLI/가짜 HTTP 응답 없음.
- AI 원본 프로젝트와 애니메이션 JSON을 사람이 수정하지 않았다. export는 기존 core의 실제 출력과4종 모두 deep-equal이었다.
- 내려받은 Lottie 원본을 독립 light player에서 렌더링했다. 30fps 전송용 영상에 쓰는 총360개 프레임과 시작/중간/종료 자세,64px/128px 이미지를 보존했다. 편집 원본은60fps이며 MP4는30fps이다.
- 렌더 브라우저의 컨테이너는512×516, 실제 SVG는 좌상단(0,0)에512×512로 놓이고 아래에4px의 inline baseline 여백이 있음을 DOM으로 확인했다. 전달 MP4만 이 외부 여백을 제외해512×512(나란히 비교1024×512)로 인코딩했다. 원본 PNG·프로젝트·JSON은 보존했고 도형 배치·형태를 고친 것은 아니다.
- 로딩/상품 MP4는 원본1주기를3번 반복한 미리보기, 성공 MP4는 원본1회 재생이다. 음악/음성은 넣지 않았다. 실패 출력도 삭제하거나 정상 출력으로 대체하지 않았다.
- provider.rs/schema/기본3개 brief의 SHA256을 검사해 비교 중 변경되지 않았음을 확인했다. 보강 결과는 별도 brief·별도 파일이다.

## 사례별 판정 — 관찰 판단, 임의 점수 없음

### 1. 로딩 루프 — 기본 UI용 사용 가능, 프리미엄 판정은 아님

-3레이어,512×512,60fps,120프레임.
- 구도/가독성: **통과**. 점3개가 균형 있게 배치되고64px에서도 구분된다.
- 움직임 구조: **통과**. 좌→중→우의 순차 상승/복귀가 있고 범위를 벗어난 가시 도형은 없다. 전 계층 시작·끝 포즈가 일치한다.
- 차별화/고급스러움: **기본 수준**. 익숙한3점 loader이며 독창적인 브랜드 모션이나 고급 일러스트는 아니다.
- 증거: `loader/preview.mp4`, `loader/contact.png`, `loader/project.moro.json`.

### 2. 결제 완료 기본 요청 — 품질 실패

-4레이어,512×512,60fps,180프레임.
- 구도: **실패**. 흰 배경은 중심(0,0), 민트 원은 중심(112,112)로 생성됐다. 현재 엔진의 x/y는 중심 좌표인데 결과는 좌상단 배치처럼 보여 원형 바탕이 왼쪽 위에서 잘린다.
- 형태/상태 전달: **실패**. 체크 획 접합에 돌출·교차가 생기고 원 밖에 걸쳐 보여,64px에서 깔끔한 완료 표시로 읽기 어렵다.
- 최종 hold: **수치상 통과**. 마지막1초는 안정적이지만 잘못된 모양을 안정적으로 유지하는 것일 뿐, 품질 합격이 아니다.
- 증거: `success/preview.mp4`, `success/contact.png`, `success/project.moro.json`.

### 3. 제품 상호작용 — 연결된 기하학적 초안, 고급 홍보 자산은 아님

-11레이어,512×512,60fps,240프레임.
- 행동 연결: **통과**. 카드 위 물체가 들려 이동하고 트레이에 안착한 뒤 배지가 나오는 상태를 순서대로 표현한다. 카드/물체/트레이/전경 lip의 층이 구분된다.
- 범위/반복 끝점: **수치상 통과**. 가시 도형의 범위 이탈은 없고 모든 계층의 양 끝 포즈가 일치한다. 끝점 일치만으로 모든 속도·루프 이음새의 미학적 합격을 보증하지 않는다.
- 작은 크기: **수정 필요**.64px에서는 물체가 매우 작고 완료 배지의 체크를 읽기 어렵다.
- 표현력: **프로토타입 수준**. 사각형·원으로 된 설명용 구성이다. 실제품 묘사, 세밀한 재질, 로고·타이포그래피·풍부한 일러스트를 제공하지 않는다.
- 증거: `product/preview.mp4`, `product/contact.png`, `product/project.moro.json`.

### 4. 결제 완료 계약 보강 — 기본 UI용으로 개선, 완전 자동 품질 보증은 아님

기본 brief를 유지하고 “x/y는 도형 중심,512 캔버스 중앙은256/256, 배경도 중앙, 체크는 교차하는 X가 아닌 끝이 이어진 V, scale/opacity100”을 추가했다. 사람이 프로젝트 좌표를 고친 것이 아니다.

- 구도/64px 판독성: **통과**. 원과 체크가 중앙에 있고 잘림이 없어졌다. 화면 밖 가시 도형0, 마지막1초 hold 안정적.
- 접합 polish: **아직 제한**. 체크로 읽히지만 두 사각형이 겹친 접합 모서리에 작은 각이 보인다. 매끈한 단일 path와 같지 않다.
- 해석: 상세 지시를 줄 때 쓸 만한 기본 아이콘으로 개선될 가능성을 보여준다. 현재 기본 생성이 항상 이 수준이라는 뜻은 아니다.
- 증거: `success-guided/preview.mp4`, `success-guided/contact.png`, `success-guided/project.moro.json`; 비교 영상 왼쪽=기본, 오른쪽=보강.

## 재생과 검증의 제한

모든 전달 MP4는 ffmpeg 전체 디코딩을 통과했다. 자동 headless Chrome에서4종 모두 끝까지 재생되고 프레임 콜백이 발생했다. 그러나 playbackQuality에는 상당한 프레임 드롭이 기록됐으므로 **이 검사로 실제 기기의 매끄러운 실시간 성능까지 합격 처리하지 않았다.** 드롭의 환경/디코더/앱 원인은 분리 검증하지 않았다. 프레임별 독립 렌더·파일 디코딩과 실제 기기 성능은 별개다. `playback.json`에 원 측정치를 포함한다.

이번 QA는 키프레임 수치·실제 자세·소형 판독성과 내보내기를 확인했다. 물리 기기, 다른 Lottie 플레이어, 호스트 앱의 reduced-motion/완료 후 정지 동작은 별도 미검증이다. 실제 프로젝트 재열기/재편집 여부를 이 품질 테스트에서 다시 실행한 것은 아니며, 원본은 기존 parser로 모두 확인했다.

## 근본 원인과 개선 우선순위

1. **제작 계약 전달 부족:** 현재 모델 입력에는 구조·단위 범위는 있지만 중심 좌표/bottom→top/키프레임 의미 등의 제작 계약이 충분히 전달되지 않는다. 실패 사례에 맞춰 중심 좌표·레이어·접합을 먼저 명시해야 한다.
2. **레퍼런스가 실제 생성 입력과 단절:** 저장소의 composition/motion/timing/looping 문서는 존재하지만 현재 빈 작업 폴더/도구 비활성 worker에 자동 주입되지 않는다. 문서를 더 만드는 것만으로 생성 품질이 올라가지는 않는다. 짧은 공통 craft capsule을 명시적으로 제공하는 방식이 우선이다.
3. **시각 피드백 고리 없음:** 현재는 한 번 생성→구조 검증이다. 화면 밖/거의 비가시/관절·체크 접합/목표 크기 판독성 경고와 실제 렌더 검토가 필요하다. fade/reset도 정당하므로 무조건 강제 보정하거나 임의 점수로 승인하면 안 된다.
4. **표현 엔진의 한계:** rect/ellipse, 정적색,5개 transform만으로 기본 UI 모션은 가능하지만, path/trim/round corner/비균일 scale/parenting 등을 요구하는 고급 모션은 현재 범위 밖이다. 먼저 실제 실패를 개선한 후 기능 확장 범위를 정해야 한다.

이번 작업은 **품질 확인과 비교 생성만** 수행했다. 제품 코드를 고쳤다거나 고품질 보장 기능이 추가됐다고 주장하지 않는다.
