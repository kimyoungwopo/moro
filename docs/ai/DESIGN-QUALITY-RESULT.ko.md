# 디자인 기준과 엔진 보강 — 실제 결과

검증일2026-10-31. 작은 완료 배지와 체크 접합을 수정한 로컬 결과다. 문서 작성만으로 완료 처리하지 않고, 실제 생성·내보내기·64px 렌더까지 확인했다. 원격 commit/push·공개 배포는 하지 않았다.

## 무엇을 바꿨나

- 기존 `DESIGN.md`의 앱 토큰은 보존했다. 생성용 기준은 `skills/lottie-authoring/references/design-system.md`, 움직임 기준은 `MOTION.md`, 체크·배지 구성은 `skills/lottie-authoring/recipes/compact-feedback.md`에 분리했다.
- 이3개 파일과 기존4개 craft reference를 실제 Rust planner 입력에 포함했다. 함수 내용뿐 아니라 두 provider subprocess의 실제 stdin 전달을 검사했다. no-tools·빈 작업 폴더·read-only·토큰 비수집 경계는 유지했다.
- Creator에 정적 `cornerRadius`와 실제 Lottie `rc.r` 내보내기를 추가했다. 생략/null/0은 기존 사각형을 그대로 유지한다. 사각형 반경은 짧은 변의 절반 이하, 원은0/null만 허용하며 잘못된 데이터는 거부한다.
- 사각형에만 Corner radius inspector를 제공한다. 적용·Undo·저장/열기·CLI와 독립 player까지 확인했다. 크기를 줄일 때 반경이 범위를 벗어나면 오류로 거부하며 몰래 보정하지 않는다.
- 생성 전 Target display size64/128/512를 선택한다. 대상 크기 변경은 동의를 해제한다. 선택값은 보이는 Design target 헤더로 요청 본문과 함께 전송되며, 캔버스 크기와 구분한다. 전체4000자 제한 안에서 본문을 자르지 않는다. 제안 검토는 제출 당시 크기를 유지한다.

## 실제 관찰한 결함도 한 번 더 수정했다

첫 둥근 체크 결과에서 작은 굴곡을 발견했다. 둥근 사각형의 전체 길이를 단순히 두 점 사이 거리로 잡으면 끝의 원 중심이 안으로 들어간다. 구성식을 `전체 폭 = 중심선 끝점 거리 + 획 두께`, 반경=두께/2로 고쳤다. 따라서 두 팔의 둥근 끝 중심이 같은 접합점에 놓인다. 이는 문서의 말투 수정이 아니라 실제 기하 구성 수정이다.

- 첫 시도 원본은 `artifacts/ai-design-quality/`에 보존했다. 끝 원 중심의 어긋남은64px 기준 약2.12px였다.
- 수정 후 `artifacts/ai-design-quality-v2/`에 별도 실제 재생성했다. 두 사례의 접합 중심 오차는64px 기준0.001px 미만이었다.
- 생성된 JSON을 사람이 고치거나 정상 레시피 출력으로 바꿔 넣지 않았다.

## 검증 결과

- 앱 단위95개·브라우저18개·Rust29개, 배포3개·문서6개 통과. lint/typecheck/build/skill 동기화도 통과했다.
- 브라우저에서 둥근 사각형의 실제 SVG를 래스터화해 모서리 픽셀이 바뀜을 확인했다. 한 번 Undo, 저장/열기, 실제 다운로드, 독립 player, 모바일390px/44px 조작부를 확인했다.
- 선택 대상 크기의 전송·동의 재확인·실제 제안 미리보기를 검사했다. HTTP fixture 검사는 모델 품질 증거와 별개다.
- 같은 사용자 요청 원문으로 결제 완료/상품 이동2종을 실제 공식 Codex CLI에서 생성했다. 기존 요청에 새 대상 크기64px 메타데이터와 개선된 신뢰 지침이 추가된 비교이며, 전체 모델 입력까지 전후 동일했다는 뜻은 아니다.
- 최종2종은 core export와 일치하고 원본 변경이 없다. 가시 도형의 전체 프레임 기하 샘플에서 캔버스 이탈0건, 결제 완료 마지막1초 안정, 상품 루프 전 계층 시작·끝 포즈 일치를 확인했다. 수치 통과만으로 미학적 합격을 주장하지 않았다.

## 두 수정 목표에 대한 판정

1. **결제 체크 접합: 이번 사례 개선 확인.** 최종64px에서 체크가 연결돼 읽히고 사각 끝의 돌출과 접합 굴곡이 줄었다.3px 획과 둥근 끝을 실제 내보내기에 사용했다.
2. **작은 상품 완료 배지: 이번 사례 개선 확인.** 최종64px에서 배지는12px, 체크 획3px, 주인공 짧은 변24px이다. 완료 표시와 주인공이 구분된다. 실제 인식 정지 구간인 frame160을 전후 같은 크기로 비교했다.

전후 영상은 왼쪽=이전 전달 결과(`ai-quality-fixed`), 오른쪽=최종 디자인/엔진/대상 크기 적용 결과다. 처음3초 결제 완료1회, 이어12초 상품 루프3회다. 편집 원본60fps, 전달 MP430fps. 실제64px PNG는 별도 보존했고, 비교 PNG는 그 원본을 최근접4배 확대한 검사 이미지다. 영상의4px 외부 inline baseline 여백만 제외했으며 도형·배치를 사후 보정한 것이 아니다.

## 범위

이번 두 대표 사례의 수정 확인이지 모든 AI·모든 요청의 고품질 보증이나 통계적 성공률은 아니다. 현재 표현 범위는 사각형/원·정적 둥근 모서리·기존5개 transform track이다. 경고는 예술적 승인이나 자동 이미지 QA가 아니며 현재 프로젝트/미리보기/경고를 모델에 자동 전송하지 않는다. 이번 실제 추론 검증은 Codex만 포함한다.

DESIGN.md 공식 CLI lint는 오류0·경고15였다. 기존 투명 배경 대비 계산 및 미참조 토큰 등의 경고가 있으므로 문서 lint 통과를 앱 전체 대비 인증으로 주장하지 않는다. Tailwind/DTCG JSON export는 제공하지만 기존 앱 CSS를 자동 교체하지 않았다.
